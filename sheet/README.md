# Setting up the Google Sheet

The map reads one tab of a Google Sheet, called `Data`, through its "publish to web" CSV link. Everything else in the sheet stays private. This guide covers the structure the map expects, the ready-made workbook that was generated for the Waterbrooke missionary sheet, and the manual steps for setting up any other sheet.

The two CSV files in this folder, `Countries.csv` and `Subdivisions.csv`, are **generated** by `tools/prep-boundaries.mjs` from the same Natural Earth data the map draws. Never edit them by hand. If the map data is ever regenerated, re-import both lookup tabs at the same time.

## What the map reads

The `Data` tab needs a header row with at least `Organization` and `Region Code`. `Country`, `State / Province`, `Country Code`, `Subdivision Code`, `Website`, and `Notes` are expected too but only `Organization` and `Region Code` drive the map.

| Row | What the map does with it |
|---|---|
| `Organization` and `Region Code` filled | Counted and listed in that region. `US-TX` is a state, `KE` is a whole country. |
| `Organization` filled, `Country` and `Region Code` empty | A global or unlocated ministry. Not placed on the map, not an error. |
| `Organization` filled, `Country` typed but `Region Code` empty | The country was not recognized. Skipped and reported in the `?debug=1` panel. |
| Everything empty | Ignored. |

**Privacy rule:** the `Data` tab is public to anyone with the link. Keep respondent names, prayer requests, goals, and anything else personal out of it. The recommended structure below does that by deriving `Data` from your working tab with formulas.

## The tabs

| Tab | Who edits it | Published? |
|---|---|---|
| Your working tab (for Waterbrooke: `Missionary Data`) | People | No |
| `Data` | Nobody; formulas derive it from the working tab | **Yes, the only one** |
| `Countries` | Nobody; imported | No |
| `Subdivisions` | Nobody; imported | No |

## Waterbrooke: the generated workbook

On 2026-09-07 the shared missionary workbook was downloaded and a map-ready copy was generated by `tools/build-sheet.py` at `D:\prototypes\org-heatmap-sheet\Waterbrooke Missionary Data (map-ready).xlsx` (kept out of this repository because it contains private data). It keeps `Missionary Data` and `Instructions & Notes` exactly as they were and adds:

- Columns J to O on `Missionary Data`: `Map Label` (public name, pre-filled with the organization, personal names removed where obvious), `Country` (dropdown, pre-filled from the Location text), `State / Province` (pre-filled where the location named one), and the three formula columns.
- The `Countries` and `Subdivisions` lookup tabs, with a `Dropdown` column on `Countries`.
- A `Data` tab derived row by row from `Missionary Data` rows 2 to 300.
- The Country dropdown and the two red-cell rules.
- A new section in `Instructions & Notes` explaining the map columns.

To put it in place:

1. Upload the file to Google Drive (or drag it onto drive.google.com).
2. Open it, then **File → Save as Google Sheets**. Publishing and formulas need a native Google Sheet; the original file was an Excel file viewed in Sheets, which cannot be published.
3. Check the pre-filled `Map Label`, `Country`, and `State / Province` values in columns J to L and fix anything you disagree with. Red cells need attention.
4. **File → Share → Publish to web**. On the **Link** tab choose the **Data** tab (not "Entire Document") and **Comma-separated values (.csv)**, leave "Automatically republish when changes are made" checked, click **Publish**, and copy the URL.
5. Paste that URL into `config.js` as `sheetCsvUrl` and commit.

If the sheet has changed since it was downloaded, either re-enter those changes in the new copy or rerun the generator on a fresh download.

## Manual setup for any other sheet

### 1. Import the lookup tabs

1. **File → Import → Upload**, choose `Countries.csv`, import location **Insert new sheet(s)**, separator **Comma**. Rename the tab to exactly `Countries`.
2. Repeat for `Subdivisions.csv`, naming the tab `Subdivisions`.
3. Each tab has a version stamp in row 1, headers in row 2, data from row 3. `Countries` columns: `Key`, `Name`, `Alpha-2`, `Canonical`. `Subdivisions` columns: `Key`, `Country Code`, `Name`, `Code`, `Canonical`.
4. In `Countries!F3` put `=FILTER(B3:B, UPPER(TO_TEXT(D3:D))="TRUE")` and give F2 the header `Dropdown`. This is the list the Country dropdown uses.

### 2. Add the map columns to your working tab

Add these columns after your existing ones (the formulas below assume they are J to O, with the organization name in column B; adjust the letters if yours differ):

| Col | Header | Filled by |
|---|---|---|
| J | `Map Label` | People. The public name. Leave blank to use the organization name. |
| K | `Country` | People, from the dropdown. Blank means global, not placed. |
| L | `State / Province` | People, free text, optional. |
| M | `Country Code` | Formula |
| N | `Subdivision Code` | Formula |
| O | `Region Code` | Formula |

Formulas for row 2, filled down (or wrapped in `ARRAYFORMULA` with `K2:K`-style ranges if you prefer them to fill themselves):

```
M2: =IF(LEN(TRIM(K2))=0,"",IFERROR(VLOOKUP(LOWER(TRIM(K2)),Countries!$A:$C,3,FALSE),""))
N2: =IF(OR(LEN(TRIM(L2))=0,LEN(M2)=0),"",IFERROR(VLOOKUP(LOWER(M2)&"|"&LOWER(TRIM(L2)),Subdivisions!$A:$D,4,FALSE),""))
O2: =IF(LEN(M2)=0,"",IF(LEN(N2)>0,N2,M2))
```

### 3. Country dropdown and red-cell rules

- Select `K2:K`, **Data → Data validation → Add rule**, criteria **Dropdown (from a range)**, range `Countries!$F$3:$F`, **Reject the input**.
- **Format → Conditional formatting**, two rules with "Custom formula is" and a red fill:

| Range | Formula | Meaning |
|---|---|---|
| `K2:K` | `=AND(LEN(TRIM(K2))>0, LEN(M2)=0)` | Country typed but not recognized |
| `L2:L` | `=AND(LEN(TRIM(L2))>0, LEN(N2)=0)` | State/province typed but not recognized |

### 4. The Data tab

Create a tab named `Data` with the header row `Organization`, `Country`, `State / Province`, `Country Code`, `Subdivision Code`, `Region Code`, `Website`, `Notes` in row 1, then in row 2, filled down as far as your working tab might grow (the working tab is called `Missionary Data` here):

```
A2: =IF(LEN('Missionary Data'!J2&"")>0,'Missionary Data'!J2&"",'Missionary Data'!B2&"")
B2: ='Missionary Data'!K2&""
C2: ='Missionary Data'!L2&""
D2: ='Missionary Data'!M2&""
E2: ='Missionary Data'!N2&""
F2: ='Missionary Data'!O2&""
```

Leave `Website` and `Notes` empty unless you have public values for them.

### 5. Publish only the Data tab

**File → Share → Publish to web → Link tab → choose `Data` → Comma-separated values (.csv) → Publish.** Copy the URL into `config.js` as `sheetCsvUrl`.

## Things to know

- **Edits take a few minutes to appear.** Google caches the published CSV for roughly five minutes.
- **Territories are countries in the dropdown.** Puerto Rico, Greenland, Hong Kong, Macao, Guam, and similar places are their own entries.
- **Small places without regions.** Puerto Rico, Vatican, Monaco, and most island dependencies have no state/province level on the map. Leave `State / Province` blank for them.
- **Cities are not regions.** Type the state or province, not the city, unless the city is itself a region (Nairobi, Bogota, Mexico City are).
- **Older subdivision schemes.** The boundary data lags some reforms. Kenya shows its 8 former provinces, not the 47 counties. If a name does not match, leave it blank so the entry still counts toward the country.
- **Two countries for one ministry.** Add a second row for the second country.
- **Blank rows are harmless.** The published CSV may include trailing blank rows produced by the formulas; the page ignores them.
- **Checking what the map sees.** Open the page with `?debug=1` to see skipped rows, not-placed entries, and codes with no shape.

## Adding an alias

If people keep typing a name the lookup does not know, add it to the alias lists in `tools/prep-boundaries.mjs` (`COUNTRY_EXTRA_ALIASES`, or `SUBDIVISION_NAME_OVERRIDES` for display names), run `npm run prep` and `npm run validate`, commit, and re-import both lookup tabs. A quick temporary fix is a row at the bottom of `Subdivisions` with `Key` = lowercase `cc|name` (for example `ke|nairobi county`), the `Country Code`, the `Name`, the `Code` it should map to, and `Canonical` = FALSE. Hand-added rows are lost when the tab is re-imported.
